> 目的：记录 Flask 后端迁移到 `backend-java` 的接口覆盖、代码位置、实现差异和待办。此文件是后续 Java 后端替换工作的进度基准。

## 后续工作的固定流程

每次开始新的后端迁移或接手中断任务时，必须先按顺序：

1. 阅读本台账，确认目标接口标记为“未迁移”还是“部分迁移”。
2. 查看本台账列出的 Java 实现位置，并重新核对对应 Flask 路由与服务代码，避免重做已有功能或把简化实现误认为完整迁移。
3. 只实现尚未覆盖的行为；如需改写已有实现，应先把该项状态和差异更新为当前实际情况。
4. 完成后更新“迁移状态表”、文件位置、遗留差异、验证记录和最后核对日期。
5. 不得仅因接口已存在就标为完成；只有主要请求/响应、权限和业务行为经过对照，才可标记“已对照”。

完成一项替换后也必须回写本台账。新增或发现的 Flask 路由要先登记，再决定实现位置。

  1. **网关启动即失败**：`predicates: [Path=/api/login,/api/register,...]` 写法会被解析成多个谓词（`/api/register` 不含 `=`）→ `Invalid predicate`。改为每个谓词一个列表项（block list）。**此前所有路由配置从未生效过**。
  2. **JWT 算法不一致**：JJWT 的 `signWith(key)` 按密钥长度自动选算法（64 字节密钥 → HS512），而 Flask 固定 HS256 → Java 签发的 token 在 Flask 侧验签失败。改为显式 `app.jwt.algorithm: ${JWT_ALGORITHM:HS256}`，签发 HS256、解析仍接受多种算法。实测签发/解码均 HS256。
  3. **历史密码无法登录**：Flask(werkzeug) 用 `scrypt:` / `pbkdf2:sha256:` 前缀，原实现只认 `$2` 开头，其余按明文比较 → 迁移后这类账号全部登录失败。新增 `PasswordVerifier` 支持 BCrypt / scrypt(BouncyCastle) / pbkdf2(JDK)，用 Python 真实生成的哈希写成 5 个单测。
  4. **时间字段格式**：`/api/user/list`、`/api/merchant/applications` 返回 `2026-04-01T23:24:48`（Jackson 的 ISO），Flask 为 `2026-04-01 23:24:48`，前端会显示多余 `T`。统一改 `date_format(...,'%Y-%m-%d %H:%i:%s')`。
  5. **网关 401/403 文案**：返回英文 `Unauthorized`/`Forbidden`，Flask 是「未登录或登录已过期」/「权限不足」。已对齐。
