# 云服务器 MySQL 导入清单（演示环境）

## 0. 先说清楚：为什么不用 `schema_dump.sql`

项目里 `.tmp/schema_dump.sql` 只有 **16 张表的结构、0 条 INSERT**——导过去是空库，商品、用户、翻译记录全没。

本目录的 `ecommerce_full_20261116.sql` 是 **mysqldump 完整导出**（5.5 MB）：

- 16 张表结构
- 20 条 INSERT（`product` 分 5 批，其余各 1 批）
- 含 `CREATE DATABASE` + `USE`，导入时不需要手动建库
- 行数与本库实测一致：product 2383 / sys_users 28 / translate_history 57 / sys_glossary 11 / publish_record 9 / biz_rec_stat_log 620

## 1. 上传

```bash
# 在你本机执行；<云主机> 换成实际 IP 或 SSH 别名
scp deploy/mysql/ecommerce_full_20261116.sql <云主机>:/tmp/
```

## 2. 云服务器装 MySQL 8

```bash
# Ubuntu 22.04 示例
sudo apt update
sudo apt install -y mysql-server
sudo systemctl enable --now mysql
sudo mysql --version     # 需为 8.0.x，项目用到 utf8mb4_0900_ai_ci collation
```

> **版本红线**：必须是 MySQL 8.0+。5.7 不支持 `utf8mb4_0900_ai_ci`，导入会报 `Unknown collation`。

## 3. 导入

```bash
sudo mysql < /tmp/ecommerce_full_20261116.sql

# 校验行数
sudo mysql -e "SELECT
  (SELECT COUNT(*) FROM ecommerce.product) AS product,
  (SELECT COUNT(*) FROM ecommerce.sys_users) AS users,
  (SELECT COUNT(*) FROM ecommerce.translate_history) AS translations,
  (SELECT COUNT(*) FROM ecommerce.sys_glossary) AS glossary,
  (SELECT COUNT(*) FROM ecommerce.publish_record) AS published,
  (SELECT COUNT(*) FROM ecommerce.biz_rec_stat_log) AS behavior;"
```

期望输出：`2383 / 28 / 57 / 11 / 9 / 620`。任一为 0 说明导入不完整。

## 4. 给 Java 服务建专用账号

不要用 `root` 跑应用。dump 里不含账号授权（mysqldump 默认不导 mysql 库），需要手动建：

```sql
CREATE USER 'ecommerce_app'@'localhost' IDENTIFIED BY '换成强密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON ecommerce.* TO 'ecommerce_app'@'localhost';
FLUSH PRIVILEGES;
```

对应到 Java 环境变量：

```bash
export DB_URL='jdbc:mysql://localhost:3306/ecommerce?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai'
export DB_USERNAME='ecommerce_app'
export DB_PASSWORD='换成强密码'
```

## 5. 引擎与排序规则自检

```bash
sudo mysql -e "SELECT @@version, @@default_storage_engine, @@collation_database;
SELECT COUNT(*) FROM information_schema.tables
WHERE table_schema='ecommerce' AND engine != 'InnoDB';"
```

第二项必须是 **0**——项目依赖 InnoDB 事务与外键行为。

## 6. 一个必须改的兼容点

dump 是从本机 MySQL 8.0.32 导出的。若云上是 **MySQL 8.0.36+ 或 MariaDB**，注意：

- MariaDB **不能用**：不支持 `utf8mb4_0900_ai_ci`，且 `information_schema` 行为不同。请用 Oracle MySQL 8.0。
- 8.0.x 各小版本之间直接导入无障碍。

## 导入完成后应用怎么连

**现在 MySQL 已经在云服务器本机了**，所以：

| 变量 | 值 |
| :--- | :--- |
| `DB_URL` | `jdbc:mysql://localhost:3306/ecommerce?...`（保持 localhost，不用改成本机 IP） |
| ES / Canal / Redis | 仍在你本机 → 仍需内网穿透，或按之前方案关掉（`ES_ENABLED=false`、`CANAL_ENABLED=false`） |

**演示最小集的推荐组合**：

- MySQL：云服务器本机（本文件）
- ES：关掉，搜索走 MySQL ngram 全文索引（dump 里已含 `ft_product_search` 索引定义）
- Canal：关掉（没有 ES 就不需要同步）
- Redis：关掉或装一个本地的（`app.redis` 有熔断降级）
- embedding：云端启 Python 服务，或关掉（推荐会降级，RAG 客服不可用）

这样**完全不依赖你的 Windows 本机**，演示时不会因断网/关机崩掉。

## 7. 验证 ngram 索引是否随 dump 带过来了

```bash
sudo mysql -e "SHOW INDEX FROM ecommerce.product WHERE Key_name='ft_product_search';"
```

应能看到一条 FULLTEXT 索引。若没有，执行项目里的修复脚本：

```bash
sudo mysql < deploy/mysql/fix_fulltext_ngram.sql
```

> ⚠️ 该脚本本身是给已有数据表加索引用的，MySQL 8 对有外键的表直接 `ADD FULLTEXT` 会失败（`FTS_DOC_ID` 冲突）。若失败，需要先建新表再 RENAME 交换——这一步在导入空库后做最省事，所以**导入后立刻验证索引**比后面补要容易。
